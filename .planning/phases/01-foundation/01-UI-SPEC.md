# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase 1 scope note:** This phase is infrastructure-first. It installs and configures the design system (`packages/ui` via shadcn CLI) and establishes the token baseline both apps will inherit. No feature screens ship in Phase 1 — only the token layer, component scaffolding, and a minimal "it works" shell for each app. The visual contracts below are the foundation that Phase 2–6 build on.

**Two-app token split:**

Both apps share the same `packages/ui` token base. Visual identity diverges at the theme layer, not the token layer:

| Token Layer | apps/web (public site) | apps/console (internal ops) |
|-------------|------------------------|------------------------------|
| Base tokens | Shared from packages/ui | Shared from packages/ui |
| Theme mode | Light-first, dark supported via `.dark` class | Dark-first (dense screens, extended use) |
| Type scale | Uses display + heading sizes (larger range) | Uses body + label sizes (compact range) |
| Border radius | `--radius: 0.5rem` (8px) — rounded, approachable | `--radius: 0.375rem` (6px) — tighter, utilitarian |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge padding, inline tight padding |
| sm | 8px | Compact element spacing, button inner vertical padding |
| md | 16px | Default element spacing, form field internal padding |
| lg | 24px | Card internal padding, section vertical rhythm |
| xl | 32px | Layout column gaps, major UI element separation |
| 2xl | 48px | Major section breaks on public site |
| 3xl | 64px | Page-level top/bottom padding on public site hero |

Exceptions:
- Touch targets (public site mobile-facing): minimum 44px height on interactive elements (WCAG 2.5.5) — achieved via `min-h-[44px]` on buttons in `apps/web`; console is desktop-first so 36px button height is acceptable
- Console sidebar nav items: 36px height (`h-9`) — Linear/Attio density reference
- Console table rows: 48px height (`h-12`) — readable at density without pixel-hunting

## Typography

### apps/web (Public Candidate Site)

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 48px (3rem) | 600 semibold | 1.1 | Hero headline, above-fold statement |
| Heading | 28px (1.75rem) | 600 semibold | 1.2 | Section headings, page titles |
| Body | 16px (1rem) | 400 regular | 1.6 | Paragraph copy, form labels, descriptions |
| Label | 14px (0.875rem) | 500 medium | 1.4 | Metadata labels, badges, secondary text, nav items |

### apps/console (Internal Ops Console)

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Heading | 20px (1.25rem) | 600 semibold | 1.3 | Page headings, modal titles, section separators |
| Body | 14px (0.875rem) | 400 regular | 1.5 | Table cells, form fields, card body copy |
| Label | 12px (0.75rem) | 500 medium | 1.4 | Column headers, metadata chips, nav labels, status badges |
| Caption | 11px (0.6875rem) | 400 regular | 1.3 | Timestamps, cost figures, secondary metadata |

**Weights:** Exactly two weights per app. No other weights. Bold (700) is never used — it creates visual noise at density.

- web: 400 regular + 600 semibold
- console: 400 regular + 500 medium (cap weight lower than web — keeps dense UIs scannable)

**Font stack CSS variable (set in packages/ui globals.css):**
```
--font-sans: 'Geist', ui-sans-serif, system-ui, -apple-system, sans-serif;
```

## Color

| Role | Light Value | Dark Value | Source |

| `--foreground` | `oklch(0.145 0 0)` | `oklch(0.985 0 0)` | shadcn new-york defaults |
| `--card` | `oklch(1 0 0)` | `oklch(0.205 0 0)` | shadcn new-york defaults |

| `--muted-foreground` | `oklch(0.556 0 0)` | `oklch(0.708 0 0)` | shadcn new-york defaults |
| `--border` | `oklch(0.922 0 0)` | `oklch(0.269 0 0)` | shadcn new-york defaults |
| `--primary` | `oklch(0.205 0 0)` | `oklch(0.985 0 0)` | shadcn new-york defaults |

### apps/web Color Contract (60/30/10)

| Role | Allocation | Value | Specific Elements |
|------|------------|-------|-------------------|
| Dominant (60%) | Background surfaces | `--background` (white, light mode) | Page background, section fills, content areas |
| Secondary (30%) | Structural chrome | `--muted` (off-white `oklch(0.961 0 0)`) | Feature section backgrounds, card fills, footer band |
| Accent (10%) | Brand calls-to-action | Override `--primary` to Brynzit brand blue: `oklch(0.546 0.215 261.3)` (≈ #2563EB, Tailwind blue-600) | Primary buttons ("Join the pool", "Apply now", "Create account"), active nav indicator, link hover state, focus rings |

Destructive: `--destructive` — reserved exclusively for delete/remove actions (if any appear in v1 public flows — none expected in Phase 1 scaffold).

### apps/console Color Contract (60/30/10)

| Role | Allocation | Value | Specific Elements |
|------|------------|-------|-------------------|
| Dominant (60%) | App background | `--background` (dark mode: `oklch(0.145 0 0)`) | Main content area, sheet backgrounds, route group fills |
| Secondary (30%) | Structural chrome | `--card` / sidebar variant `oklch(0.185 0 0)` | Sidebar background, nav rail, card surfaces, table header rows |
| Accent (10%) | Action-critical elements | `oklch(0.546 0.215 261.3)` (blue-600) — consistent with web | Primary action buttons (Approve, Save, Confirm), active nav item highlight, focus rings, checkbox checked state, selected row highlight |

Destructive: `--destructive` (red) — reserved for Reject, Delete, and Remove actions only. Never used for neutral state changes or warnings.

**Second semantic color — warning (console only):**
`oklch(0.769 0.188 85.87)` (amber-400) — reserved for quota usage above 80% (ADM-03), failed async job states, and snooze-wake badges. Not used in Phase 1 — token declared now so Phase 2 can reference it.

## Copywriting Contract

Phase 1 ships scaffolding, not feature screens. Copywriting here governs the initial shell states visible during scaffolding and any `useAsyncJob` primitive states.

| Element | Copy | Context |
|---------|------|---------|
| apps/web shell page title | "Brynzit — Find your next role" | `<title>` in root layout; SEO-ready from first commit |
| apps/console shell page title | "Brynzit Console" | `<title>` in root layout; no public branding needed |
| apps/web root page placeholder | "Brynzit is coming." / "The talent platform built for speed." | Placeholder until Phase 5 landing page ships |
| apps/console root page placeholder | "Console" with nav skeleton | Functional shell, no placeholder copy needed |
| useAsyncJob: polling state | "Processing…" | Generic label in the primitive; callers override with context-specific copy |
| useAsyncJob: success state | "Done" | Generic terminal success; callers override |
| useAsyncJob: failed state | "Something went wrong. Try again." | Concise: problem statement + action path in 5 words |
| useAsyncJob: timeout state | "Taking longer than expected. Refresh to check status." | Covers network interruptions; gives user a recoverable path |
| Error boundary fallback heading | "Something went wrong" | Root error boundary in both apps |
| Error boundary fallback body | "Reload the page — if the problem continues, the team has been notified." | Accurate: team monitors; gives user one action |
| 404 page | "Page not found" / "This page doesn't exist. Return to home." | Both apps; "home" links to respective app root |

Destructive actions in Phase 1: None. Phase 1 ships no destructive interactions. Destructive confirmation pattern (5-second undo toast, per CUX-02) is implemented in Phase 2.
