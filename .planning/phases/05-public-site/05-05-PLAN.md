<task type="checkpoint:human-verify" gate="blocking">

Complete Phase 5 public site — landing page, job board with gating, signup, login, 3-step onboarding (resume upload + profile confirm + preferences), job detail with JSON-LD, apply flow, and profile edit with completeness meter.
  </what-built>
  <how-to-verify>
Walk through each route with `NEXT_PUBLIC_API_MOCKING=enabled` (MSW active):

**1. Landing page (PUB-01)**
- Visit http://localhost:3001/
- Confirm: Large ~120px light-weight headline (not bold, not small). White background. Minimal layout.
- Confirm: "Join the talent pool" button links to /signup
- Confirm: SiteNav shows "Brynzit" wordmark + "Jobs" link + "Sign in" ghost + "Join free" filled button
- Reference standard: contrario.ai — editorial white, generous negative space, single CTA

**2. Job board (JOB-01, JOB-05, JOB-06)**
- Visit http://localhost:3001/jobs
- Confirm: 6 job cards load from MSW (not empty), each shows title, company, location, badges
- Confirm: First 4 cards are fully visible; cards 5+ are blurred
- Confirm: "See all matching roles" overlay appears over blurred cards with "Join for free" CTA
- Confirm: Typing in search input does NOT trigger immediate refresh — waits ~350ms
- Confirm: Changing Role type dropdown triggers immediate card refresh
- Confirm: Active filter pills appear below filter bar; × button removes the pill
- Confirm: No "Strong match" or "Partial match" badges visible when logged out

**3. Signup + Onboarding (PUB-02, PUB-03, PUB-04)**
- Visit http://localhost:3001/signup
- Confirm: Form has First name, Last name, Email, Password fields
- Submit with invalid email → inline error appears
- Submit with password < 8 chars → inline error appears
- Fill valid details → lands on /onboarding/1 (Step 1 of 3 indicator visible)
- Confirm: Dropzone present with Upload icon and "Drag & drop or click to upload" label
- Click "Skip for now" → navigates to /onboarding/2
- Confirm: Step 2 shows profile fields (may be prefilled or empty)
- Click "Save & continue" with name fields filled → navigates to /onboarding/3
- Confirm: Step 3 shows location, remote preference, seniority, GitHub URL, LinkedIn URL
- Click "Skip for now" → navigates to /jobs

**4. Job board (logged-in state)**
- After completing onboarding, navigate to /jobs
- Confirm: All cards now visible (no blur, no overlay)
- Confirm: Some cards show "Strong match" or "Partial match" badges (match_strength in mock data)
- Confirm: SiteNav now shows avatar dropdown in top-right (not Sign in/Join free)
- Click avatar → dropdown shows "My Profile" and "Sign out"

**5. Job detail + Apply (JOB-02, JOB-03, JOB-04)**
- Click any job card → navigates to /jobs/[id]
- Confirm: Job title (large), company + location row, compensation (if present), badges, all skills
- Confirm: Full job description text visible below separator
- Confirm: Open browser DevTools → Elements → search `application/ld+json` → script tag present with JobPosting JSON
- Confirm: Open browser DevTools → Elements → search `canonical` → `<link rel="canonical" href="https://brynzit.com/jobs/[id]">` is present in `<head>` (D-10)
- **Google Rich Results Test (JOB-03):** Run https://search.google.com/test/rich-results on the job detail URL. If the test reports zero errors with JobPosting structured data, the client-side approach is sufficient. **If it fails with "no items detected"**, Googlebot is not executing the client-side `useEffect` — the executor MUST implement the RSC `generateMetadata` approach for canonical and server-rendered JSON-LD before phase sign-off. Do not approve the phase with a failing Rich Results Test.
- Confirm: Apply section shows correct state:
  - If score = 65 (mock default): shows "Complete your profile" button + progress bar + gate message
  - After editing profile to score ≥ 70: shows "Apply now" + optional note field
- If Apply now visible: submit → "Application submitted." toast appears

**6. Profile edit (PUB-05, PUB-06)**
- Visit http://localhost:3001/profile/edit
- Confirm: Page shows "Edit profile" heading
- Confirm: Progress bar visible with percentage label (65% complete by default)
- Confirm: Gate label "Reach 70% to unlock 1-click apply" visible
- Confirm: All 4 sections present: Personal, Skills, Preferences, Links
- Update a field → click "Save changes" → "Profile saved." toast appears
- Navigate back to /jobs/[id] apply section → score should reflect updated value

**7. Security spot-check**
- In browser URL bar, try: http://localhost:3001/signup?redirect=//evil.com
- Confirm: After signup, redirect goes to /jobs (not //evil.com) — open redirect mitigated
