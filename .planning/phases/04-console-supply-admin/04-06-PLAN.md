<!-- Reject with 5-second undo toast (CUX-02 pattern) -->
```typescript
const rejectTimeoutRef = useRef<ReturnType<typeof setTimeout> | null>(null)

function handleReject() {
  toast('Sequence rejected.', {
    duration: 5000,
    action: {
      label: 'Undo',
      onClick: () => {
        if (rejectTimeoutRef.current) {
          clearTimeout(rejectTimeoutRef.current)
          rejectTimeoutRef.current = null
        }
      },
    },
  })
  rejectTimeoutRef.current = setTimeout(async () => {
    try {
      await apiClient.POST('/api/v1/supply/engagement/{sequence_id}/reject', {
        params: { path: { sequence_id: sequence.id } },
      })
      queryClient.invalidateQueries({ queryKey: ['supply-engagements'] })
      onOpenChange(false)
    } catch {
      toast.error('Rejection failed — try again.')
    }
    rejectTimeoutRef.current = null
  }, 5000)
}

// Cleanup on unmount:
useEffect(() => () => { if (rejectTimeoutRef.current) clearTimeout(rejectTimeoutRef.current) }, [])
```

| Boundary | Description |
|----------|-------------|
| EngagementSequenceSheet step edits → PATCH + POST | User-edited step content submitted to backend |
| Reject undo timeout → POST reject | Time-delayed POST firing from browser after user action |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06-01 | Tampering | Engagement step subject/body content | mitigate | Content submitted as typed `EngagementStep[]` body — validated by typed openapi-fetch client at compile time; backend validates content server-side |
| T-04-06-02 | Tampering | Step content display (subject/body) | mitigate | Step content rendered in `<Input>` and `<textarea>` (value prop) — not dangerouslySetInnerHTML; no XSS surface in the UI |
| T-04-06-03 | Denial of Service | Reject undo timeout memory leak | mitigate | useRef cleanup in useEffect return function clears the timeout on sheet unmount; no zombie timeouts |
| T-04-06-04 | Elevation of Privilege | Engagement approve/reject without auth | accept | Trusted-network internal tool; no auth in v1 — same model as all other console actions |
