## What Was Built

### Task 1: globals.css Token Foundation

Rewrote `apps/web/app/globals.css` to establish the warm editorial palette as the CSS custom property foundation for the entire Phase 5.1 polish pass:

- `--color-primary: oklch(0.55 0.15 35)` — warm amber/terracotta replacing blue-violet `oklch(0.546 0.215 261.3)`
- `--color-ring: oklch(0.55 0.15 35)` — focus ring tracks the accent; propagates to all shadcn components (Input, Button, Select, etc.) with zero component edits needed
- `--color-background: oklch(0.99 0.003 30)` — warm near-white (~#FAFAF8) in `:root` so Tailwind's `from-background` gradient utility used by the locked-jobs overlay fades to the correct warm tone
- `--radius: 0.625rem` — slight radius increase from 0.5rem for editorial softening
- Deleted the entire `.dark {}` block — POL-07 compliance; the site is light-only and the dormant block posed dark-mode leakage risk

The override lives exclusively in `apps/web/app/globals.css` and shadows the shared `@theme {}` values from `packages/ui/src/styles/theme.css`. The shared theme is untouched, so `apps/console` is unaffected.

### Task 2: visual-polish.test.tsx Scaffold

Created `apps/web/src/__tests__/visual-polish.test.tsx` following the existing `landing.test.tsx` convention (static-analysis `fs.readFileSync` + `toContain` assertions — no rendering required for CSS/class assertions).

Contains the `describe('globals.css token foundation (POL-06, POL-07)')` block with 8 assertions:
1. Warm accent primary token set
2. Focus ring tracks the accent
3. Warm near-white background set
4. Background in `:root` not `body {}` (Pitfall 2 — gradient match guard)
5. Radius bumped to 0.625rem
6. No `.dark` block remains
7. Old blue-violet primary gone
8. Tailwind and shared theme imports preserved

All 8 tests pass. This file is the scaffold that Plans 02, 03, and 04 in this phase extend with their own `describe` blocks.
