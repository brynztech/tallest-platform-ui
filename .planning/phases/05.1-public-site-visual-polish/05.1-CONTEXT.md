# Phase 5.1: Public Site Visual Polish - Context

**Gathered:** 2026-06-15
**Status:** Ready for planning
**Source:** User direction (inline during plan-phase initiation)

<domain>
## Phase Boundary

A focused visual polish pass over `apps/web` only — no feature additions, no new API calls, no new routes. Every screen in apps/web that was built in Phase 5 (landing, job board, auth/signup, onboarding, job detail, profile/apply) needs to feel like a polished candidate-facing brand rather than a wireframe or shadcn utility output.

**In scope:** CSS/Tailwind token refinement, component visual layer, hover/focus/motion states, palette coherence, border radius/shadow softening, the four specific surfaces listed below.
**Out of scope:** apps/console UI, new features, new routes, API changes, MSW handler changes.

</domain>

<decisions>
## Implementation Decisions

### Design Aesthetic (Locked)
- **Reference:** Contrario.ai — editorial typography, clean whitespace, large restrained type
- **Mode:** Light-only. No dark-mode support in apps/web. No `dark` class on `<html>`. No dark-specific Tailwind utilities.
- **Palette:** Warm amber/terracotta accent — `oklch(0.55 0.15 35)` range. Background near-white `#FAFAF9`. Text near-black. Replace existing blue-violet primary.
- **Typography:** Large, light-weight headings; editorial register; not SaaS-dashboard weight
- **Borders:** Softer — use `border-border/50` or equivalent, not heavy black `border-foreground` style
- **Shadows:** Subtle — no aggressive box shadows
- **Gradients:** Forbidden — no `bg-gradient-*`, no AI-purple backgrounds

### Target Surfaces (All 6 required)
1. **Landing hero** — editorial headline, single accent CTA, no gradient background, proper whitespace rhythm
2. **Job board cards** — softer border, refined spacing, hover lift/tint state, no card-heavy utility appearance
3. **Auth forms (login + signup)** — consistent field spacing, softer focus rings, visual hierarchy that doesn't look like a shadcn default
4. **Onboarding steps** — consistent with auth form polish, progress bar/indicator polish
5. **Resume upload dropzone** — crafted idle / drag-over / uploading / done states (not raw dashed-border utility)
6. **Locked-jobs overlay** — tasteful blur or fade treatment, CTA that is clear but not aggressive, consistent with palette

### Motion Rules (Locked)
- Hover transitions: ≤150ms ease-out
- Focus rings: consistent across all inputs — single style defined in globals.css or theme.css
- No bouncy/springy animations on functional UI (only on decorative elements if any)
- Avoid Tailwind `transition-all` — be specific (`transition-colors`, `transition-shadow`)

### Implementation Approach (Locked)
- Refine `packages/ui/src/styles/theme.css` CSS variables first (palette, radius, shadow tokens)
- Update `apps/web/app/globals.css` for web-specific overrides (focus ring style, body typography)
- Then update individual component files in apps/web — landing page, job board, auth/onboarding, etc.
- Do NOT touch packages/ui component source unless fixing something shared — keep polish web-specific

### Claude's Discretion
- Exact colour values for refined palette (stay within the existing neutral/slate family unless tokens warrant change)
- Whether to define a shared `card-hover` utility class in globals.css or inline per component
- Specific animation easing curve beyond "ease-out ≤150ms"
- Whether resume dropzone uses a separate component file or stays inline in the onboarding page

</decisions>

<specifics>
## Specific Ideas

- Contrario.ai uses a very light background (#FAFAF9 range), near-black text, and one warm accent — not blue
- Focus ring: replace generic outline with a soft inset ring matching the accent colour
- Job card hover: subtle background tint + slight translateY(-1px) shadow lift — not aggressive
- Locked-jobs overlay: frosted-glass blur (backdrop-blur-sm) with a gradient-to-transparent fade at the bottom edge, not a hard cut
- Landing CTA button: should be the single accent colour, not outlined or ghost — the one prominent action
- Onboarding progress: linear bar using accent fill, not a circle/stepper if current is dot-based

</specifics>

## Deferred Ideas

- Dark mode for apps/web (explicitly out of scope — light-only decision is locked)
- Animation on decorative elements (keep scope to functional UI states only)
- apps/console visual polish (separate phase if ever needed — console is internal tool)

</deferred>
