## What Was Built

### ResumeDropzone Component (POL-04)

Created `apps/web/app/onboarding/_components/resume-dropzone.tsx` — a crafted file upload component replacing the raw dashed-border `<label>` in onboarding step 1.

**5 visual states with CSS class priority ordering:**
- **drag-over (highest priority):** `border-primary bg-primary/5 ring-2 ring-primary/30` — primary-tinted ring on drop target
- **failed:** `border-destructive/50 bg-destructive/5` — warm red tint with AlertCircle icon
- **file-selected (idle + file present):** `border-primary/40 bg-primary/5` — primary tint with FileText icon + filename
- **busy (uploading/processing):** `border-border/50 bg-muted/30` — muted treatment
- **idle (default):** `border-border/70 bg-card hover:bg-muted/50 hover:border-border` — clean card with UploadCloud icon

**HTML5 drag API wired correctly:**
- `onDragEnter`: sets `isDragOver` (respects `disabled` prop)
- `onDragOver`: calls `e.preventDefault()` — mandatory or browser ignores `onDrop`
- `onDragLeave`: clears `isDragOver`
- `onDrop`: `e.preventDefault()`, reads `e.dataTransfer.files[0]`, calls `onChange`

Click-to-upload path preserved via hidden `<input type="file">` with `onChange` calling `onChange` prop.

Transition uses `transition-[color,box-shadow,background-color]` (valid bracketed multi-property form) — avoids invalid `transition-shadow`.

## Deviations from Plan

### Minor: Test file written as complete content in Task 1 (not a stub)

**Rule:** No deviation rule — this is an implementation choice within plan scope.

The plan called for a "stub" test file in Task 1, then "complete" in Task 3. Since the static-analysis test file's content is fully specified in the plan and has no dependency on Task 2's implementation completing (it reads files via `fs.readFileSync`), the complete content was written upfront. Task 3 effectively verified the tests pass against the Task 2 implementation. No functional difference from the plan's intent.

### Minor: getStateClass() helper extracted from inline cn() call

The plan showed a nested ternary inside `cn()`. Extracted to a `getStateClass()` helper function for readability. Same runtime behavior, same priority ordering, easier to reason about.
